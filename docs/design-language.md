# Velai design language — one system, Search surface is the reference (decided 2026-09-18)

Reference surface: `/jobs` search (`src/app/jobs/page.tsx`, `src/components/jobs/*`, `src/components/ui/chip.tsx`). Every other surface conforms to it. No second skins: the Carbon 0-radius skin (`rounded-none` on panels/controls) and `.elite-signal` are retired. Tokens come only from `src/app/globals.css`; never add a token, a hex/rgb literal, an arbitrary `[…]` value, a shadow, a blur or a gradient.

## 1. Radius — three roles, never a size name
- `rounded-panel` (16px): any bordered/floating container — engaged search dock, detail pane, suggestion panel, empty-state panel, dialog, sheet (top corners when bottom-anchored), popover, dropdown, logo/avatar tile.
- `rounded-ctl` (12px): every control — button, icon button, input, select, textarea, toolbar segment, tab.
- `rounded-pill`: chips, filter pills, the desktop search field/dock at rest, status dots, spinners, count badges, avatars.
- `rounded-none` is allowed ONLY on list rows and full-bleed dividers (rows sit on the shared inset, they are not cards). Never `rounded-sm|md|lg|xl|2xl|3xl|full`, never `rounded-[…]`.

## 2. Surfaces, borders, focus
- Page ground `bg-background`; content `bg-card`; hover and selected `bg-muted` (selected = hover tint, nothing else); chips `bg-background border-border`. Overlays and bars: §9.
- One border weight: `border border-border`. Emphasis = `border-foreground` (active chip, focused control). Dashed border only for "nothing here" panels.
- Focus: controls `border-foreground`; dock adds `ring-1 ring-foreground`; rows `focus-visible:ring-2 ring-inset ring-brand`.
- No shadows (every `--shadow-*` token is `none`), blur only in the glass utilities listed in §9 (navigation and overlay layer), no gradients except the phone top bar's `scroll-edge` fade, no `style={{…}}` for anything a class can express (mask-image on scrollers is the one sanctioned inline style).

## 3. Type — five sizes, three weights
- `text-xs` meta/ages/counts/badges · `text-sm` secondary body, meta lines, chips, controls · `text-base` row titles, detail body, inputs · `text-xl` section headings, detail stat · `text-2xl` page title. Nothing else.
- **Heading scale — components own the size.** Every `<h1>` is `<PageTitle>` (28px), section headings `<SectionTitle>` (20px), sub-headings `<SubTitle>` (16px) — `src/components/ui/heading.tsx`, semibold/snug/balanced; a call site passes spacing only. A raw h2–h6 may take `text-xs|sm|base|xl` and nothing else. Long-form copy (About, legal, research, SEO hubs) is `<Prose>` (`src/components/ui/prose.tsx`), never a hand-rolled `prose` class.
- Weight: `font-semibold` for titles and counts; default weight everywhere else (the named weights alias to 400/600 — do not write `font-medium|bold`). The one 500 is the button face (§5), set by `.ctl-button`, never written at a call site; layout.tsx loads it as its own cut (static 400/500/600).
- Leading: `leading-snug` titles · `leading-relaxed` long body · `leading-none` single-line controls. Numbers `tabular-nums`. Ages/ids/stats `mono-data`.
- Never `text-[…]`, `leading-[…]`, `tracking-*`, `uppercase` outside `mono-data` labels.

## 4. Row anatomy (every list: jobs, applications, history, saved searches, résumé sections, settings groups)
`grid grid-cols-[auto_minmax(0,1fr)] gap-x-3 px-[var(--list-inset)] pt-4` · inner `border-b border-border pb-4` (divider inset past the leading tile) · title `text-base font-semibold leading-snug line-clamp-2` (read/secondary → `text-muted-foreground`) · lines 2–3 `mt-1 text-sm text-muted-foreground` (strong fact → `font-semibold text-foreground`) · right rail `mono-data text-xs leading-none text-muted-foreground` · hover/selected `bg-muted`. Horizontal padding on rows, list headers and toolbars is ALWAYS `px-[var(--list-inset)]` — never a literal `px-4`/`px-6`.

## 5. Controls
- **Control scale — the only heights.** `ctl-sm` 24px (segment, inline clear), `ctl-md` 32px (default button, chip, toolbar, header CTAs, tabs), `ctl-lg` 44px (input, select, form/search button — the whole search row). Tokens `--control-h-sm|md|lg` in globals.css; primitives pick a step through `size`, a call site never writes `h-*`/`min-h-*`/`py-*` on a control. Controls in one row share one step. The 44px touch target is an invisible coarse-pointer hit area (`--hit-min`), never a taller visual. Gate: `tests/unit/control-scale.test.ts`; exemption = on-line `control-scale-allow: <reason>`.
- **Button type rides on the step (2026-09-29).** 24px → 12px, 32px → 14px, 44px → 16px, all at weight 500, on the control corner (`rounded-ctl`). The map lives once, beside the heights: `--control-text-sm|md|lg` + `--control-weight` in globals.css, carried by `.ctl-sm|md|lg` and painted by `.ctl-button`. The Button primitive carries the face; a raw `<button>` on a step adds `ctl-button` beside its `ctl-*`; a face with no step of its own takes its nearest stepped ancestor's type (the header's docked Search), or the text around it (a `size="link"` inline link). A call site never writes a text size, weight or rounding on a button (text colour is fine). Buttons sit on 32px; 44px is for inputs/selects and the /jobs Search submit that shares their row. Inputs and selects keep their own type (16px at 400). Gate: `tests/unit/control-type.test.ts` (`scripts/design/control-type.cjs`); exemption = on-line `control-type-allow: <reason>` (a chip-shaped button keeping the pill, a flush list row, a joined segment half).
- Primary button: Button primitive default variant, no type or corner classes (see the /jobs Search button). Secondary: `border border-border bg-card`. Ghost: no border, `hover:bg-muted`. Height and type from the control scale above.
- Chip: `chipVariants` (`ctl-md rounded-pill border border-border bg-background px-3 text-sm tabular-nums`), active `border-foreground`; count badge as in `chip.tsx`.
- Segment/tab: bare-button recipe — `ctl-md ctl-button px-3 leading-none`, pressed = `underline underline-offset-2` (no fill).
- Input/select/textarea: `rounded-ctl border border-border bg-card ctl-lg px-3 text-base`, focus `border-foreground`; clear buttons `ctl-sm ctl-square rounded-ctl bg-muted`.
- **Wrap row.** A row of controls that may wrap is `.wrap-row` (globals.css), not `flex flex-wrap`: its items are inline boxes under `text-wrap: balance`, so the last control never strands on a line of its own. Gap via `[--wrap-gap-x:…]`/`[--wrap-gap-y:…]`; space the row with padding (its block margin is the primitive's).
- Links inside copy: `text-foreground underline-offset-2 hover:underline`.

## 6. Panels, headers, empty, loading
- **Page container — one width, one gutter.** Every page body is `<PageContainer>` (`src/components/layout/PageContainer.tsx`) or a `.shell-row` — the TopBar's own geometry (72rem → 80rem at xl; 16/32/40px gutter), so a page's left edge is the logo's. `measure="reading"` narrows the content to 48rem on that same left edge; never centre a narrow column with `mx-auto max-w-* px-*`. Tabs of one page share one frame: a tab never picks its own width (Settings' form tabs did, 2026-10-31). An "On this page" list is a rail to the right of the article, never a column that pushes the article off the logo edge.
- **Page top and masthead — one of each.** A page's masthead starts `--page-top` (40px, `.page-top`, globals.css) below the header on every route. `<PageHeader>` is the one masthead (title, `PageLead`, actions; there is no compact or sticky variant); a page that opens with its own title writes `page-top` on its container and uses `PageEyebrow` / `PageTitle` / `PageLead` (`src/components/ui/heading.tsx`). Never a per-page `py-*` above the title.
- **Named centred layouts (the only ones).** The /jobs front door (a centred search column) and the single-task card (`RouteStatusLayout`: sign-in, reset, verify, 404, error). Anything else sits in the frame.
- List header line: `flex justify-between gap-3 px-[var(--list-inset)] py-2 text-sm text-muted-foreground`, count `font-semibold text-foreground tabular-nums`.
- Empty state: left-aligned, `py-8`, `text-sm text-foreground`, exactly one Next action (conveyor rule: nudge the next station, never a tangent).
- Loading: `skeleton-bar` bars shaped like the row anatomy; status line `pt-8 text-sm text-muted-foreground` left-aligned; spinner `animate-spin rounded-pill border-2 border-brand`.
- "Nothing here / gone" panels: `rounded-panel border border-dashed border-border bg-card px-6 py-16`.

## 7. Icons, spacing, colour, mobile
- Phosphor only, `size={16}` default; 20 in the tab bar; 24 only in a hero. Button slot `[&_svg]:size-4`.
- 4px grid; sibling gaps `gap-2/3/4`; never per-element margins where a `gap` works.
- Colour only via tokens: `brand`, `live`, `warn`, `danger-text`, `st-*` (tracker stages), `verdict-*`. No hex/rgb in TSX.
- Phone: 16px inset via `--list-inset`; the dock: every bar pinned to the bottom of a phone screen is one floating glass capsule (`dock-capsule`, globals.css: inset 16px from both sides, 28rem at most, fully rounded, see-through glass at alpha 0.6 with blur) lifted off the bottom edge by `--mobile-bottom-gap` (20px, or the device inset if larger) and stacked upward from it: the tab bar is the lowest capsule, a bar above it (the job page's Apply bar) sits at `--dock-above-tabbar`. While a person scrolls down a page that has an accessory capsule (the job page's Apply bar), the dock minimizes the way Apple's tab bar does: the tab bar shrinks to one round button (the current tab; a tap expands it) and the accessory sits beside it on the same row, back to the full stack on a short scroll up, at the top, or at the end of the page (`dock-minimize.ts`, `<html data-dock>`). Never a flush band, never an offset of its own; `bottom-dock.test.ts` fails a new fixed/sticky bottom element that is not a dock capsule or a named floating notice, and J-MOB-30/31 measure the result. The space the tab bar takes is `--mobile-tabbar-h`; sheets bottom-anchored with `rounded-panel` top corners; nothing wider than the viewport (layout-audit classes A–E clean at 390 and 1440).

## 8. Enforcement
`tests/unit/design-language.test.ts` + `scripts/design/banned-classes.cjs` keep banning arbitrary values. A per-surface ratchet (`design-token-baseline.json`) pins the count of off-token classes per surface (`rounded-none`, size-named radii, `text-[`, `h-[`, `w-[`, `p-[`, hex, `shadow-`, `style={{`); a count may only go down, and a PR that lowers it must lower the baseline too. `tests/unit/page-scale.test.ts` (`scripts/design/page-scale.cjs`) fails a hand-rolled page container, an h1/heading component that writes its own size, an off-scale h2–h6, and a bare `prose`; exemption = `page-scale-allow: <reason>` on the line or just above it. Journeys J-NAV-35–37 (`page-scale.spec.ts`) check the rendered result: no stranded control on a wrapping row, the page column on the logo edge, every h1 at 28px. J-NAV-47/48 and J-SETTINGS-37 (`page-frame.spec.ts`) measure every frame page at 1440, 1280, 768 and 390: content from the logo edge to inside the header's right edge, the title on the logo edge, the masthead at `--page-top`, no sideways scroll, and Settings' tabs in one frame; a new page is added to its route list. `tests/unit/control-type.test.ts` fails a button that sets its own text size, weight or corner, or sits on 44px without a reason; journey J-NAV-38 (`control-scale.spec.ts`) reads every rendered button face's type against its step.

**Linux headless Chromium PNG captures:** use `linuxChromiumVisualQaLaunchOptions()` from `scripts/design/linux-chromium-visual-qa.cjs` (see `docs/design/DESIGN-LANGUAGE.md` § Visual QA capture fidelity). Default hinting splits labels in screenshots; `--font-render-hinting=none` fixes capture only — not a CSS change. Headed Xvfb does not fix it.

## 9. Interaction — one behaviour per kind (2026-11-02, after Claude's apps)
Claude's phone and desktop apps keep one visual and interaction language: every sheet opens the same way, every menu the same way, every row answers a tap the same way. Velai follows that, on Apple's HIG.
- **Glass on the navigation and overlay layer only** (HIG Materials): `material-bar` (laptop top bar), `scroll-edge` (phone top bar), `material-float` (dock capsules), `material-glass` (every sheet, dialog, alert, menu, popover, select, combobox, toast), `glass-group` (top-bar controls), `glass-selected` (the current tab). Content stays flat on `bg-background`/`bg-card`. A call site never paints a fill, shadow, corner or motion over an overlay primitive (`mobile-overlays.test.ts`, `interaction.test.ts`).
- **Radius roles** (adds to §1): `rounded-ctl` 12px also draws a list row's lens; `--radius-sheet` 32px is the phone sheet only (it floats 8px off the screen edges, concentric with the device corner); every other overlay is `rounded-panel`.
- **One drawer.** On a phone every Sheet and Dialog is the same bottom sheet: 8px off the sides and bottom, a grabber, then one header row (title 16px semibold on the left, the × at the right, 20px down, 16px in), the body, and an optional footer bar. The header is `SheetBar` on a Sheet and `DialogHeader` + the Dialog's × on a Dialog; both draw the × with `overlayCloseClass`. No hairline under the header. A swipe down closes it; so does Escape and a tap on the scrim. An alert (`AlertDialog`) stays centred, as Apple's alerts do. On a laptop a Dialog is centred with the same header row.
- **One overlay title size**: 16px semibold (`dialogTitleClass` = the Sheet bar's title). A form that is also a page (sign-in) drops its page masthead inside an overlay (`inOverlay`).
- **Two motions.** Modal surfaces (sheet, dialog, alert, toast, their scrims) use `motion-modal`: in 280ms easing out, out 180ms easing in. Popover surfaces (menu, select, popover, combobox, tooltip) use `motion-pop`: 150ms in, 100ms out. Expanders (accordion, `<details>` disclosure) use `motion-expand` / the disclosure's height transition at `--transition-panel`. Reduced motion zeroes all of them.
- **One press.** A Button scales (`.designed-press`); anything else tapped — chip, tab, tab-bar item, row, disclosure, accordion row, the × — lights with the hover fill while pressed (`press-fill`, and `list-row` has it built in). Touch has no hover, so every tap answers with this.
- **One list row.** Every tappable list row (jobs, related jobs, History, tracker, follow alerts) is `list-row`: a rounded lens inset 6px from the list's edges, text on the 16px `--list-inset` line, hover/press/selection drawn inside the lens. A group of rows on one fill (an employer group) keeps its flush block.
- **One inline action.** A text button or link inside a line or a toolbar is `text-action`: the brand colour at the weight of the text around it, underlined on a touch screen and on hover elsewhere (the Button `link` variant is the same). Links that name a thing (a company, a job title) stay in the text colour.
- **One notice.** A toast is a `material-glass` panel on `rounded-panel`, in on the modal motion; its kind shows in its icon.
